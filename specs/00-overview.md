# 00 · 产品范围与术语

## 使用场景

一位老师 / 主理人，带 5 个左右的英语小班（每班 10 人以内），不同班在一周的不同时间点上课。
学生按课次购买课包，上课时点名扣课时。老师需要随时知道：今天上什么课、谁该续费、这个月挣了多少。

- **单用户**，不做登录、不做角色权限
- **纯本地**，数据只在这台 Mac 上，不上云、不联网同步
- **macOS 桌面端**，窗口基准尺寸 1360×880

## MVP 范围（做）

1. 班级与循环排课规则，按周批量生成课次
2. 课表周视图，单次课取消 / 临时加课
3. 点名扣课时（出勤 / 迟到 / 请假 / 缺勤四态）
4. 课时账本：消费、充值、抵扣、调整全流水可追溯
5. 余额可为负（欠课时），充值时抵扣
6. 学生列表与详情、按余额预警
7. 经营报表：课消课时、课消收入、充值收款、出勤率、班级满员度
8. 设置：课时规则、提醒预警、班级与课包默认值、机构信息、数据备份

## 非目标（明确不做）

- 家长端 / 学生端。所有提醒只给老师自己看，不自动发给家长
- 多老师、多校区、权限体系
- 在线支付、发票、税务
- 云同步、多设备
- 课程内容管理、作业、成绩
- 自动跳过法定节假日（用户明确选择手动处理）
- 单个学生的补课排期（只支持"临时加课"，谁上课在点名时定）

## 术语表

开发中统一用这套词，代码标识符用括号里的英文。

| 中文 | 英文 | 含义 |
|---|---|---|
| 学生 | `student` | 在读的孩子 |
| 班级 | `klass` | 固定的一群学生 + 固定时段（`class` 是保留字，代码里用 `klass`） |
| 在班关系 | `enrollment` | 某学生在某班的一段时间 |
| 循环规则 | `recurrence_rule` | 「周二/周四 14:00–15:30 A 教室」这样的计划，本身不产生课 |
| 课次 | `session` | 一节具体的课，有日期。由规则生成，或临时加课 |
| 点名记录 | `attendance` | 某学生在某课次的出勤状态 |
| 课包 | `package` | 一次充值：N 课次 + 总金额，单价由两者相除得出 |
| 课时流水 | `ledger_entry` | 账本分录，余额的唯一来源 |
| 课时 / 课次 | hours / sessions | **同一个单位**。课包按"课次"卖，余额按"课时"记，1 课次 = 1 课时 |
| 欠课时 | owed | 余额为负的部分 |
| 抵扣 | offset | 充值时用新买的课次冲掉欠的课时 |
| 冲正 | reversal | 用一条反向分录修正历史，不改原记录 |
| 未消耗课时 | unconsumed | 所有正余额之和，等于教学负债（预收） |

## 关键的产品判断（别在实现时"优化"掉）

- **缺勤不扣课时。** 只有出勤和迟到扣。请假和缺勤都是 0，但两者仍分开记录，因为出勤率统计和"要不要找家长聊"不一样。
- **课包不设有效期。** 用完可以继续上，超出部分记为欠课时。
- **取消课次不顺延。** 取消就是少上一次，不往后补。
- **未消耗课时和欠课时不互相抵消。** 报表里分开列：612 课时是你欠家长的课，3 课时是家长欠你的钱，混在一起算净额会把两个问题都藏起来。
- **单价不是设置项。** 每笔充值填「课次 + 总金额」，单价现算并逐包保存。同一个学生不同时期的课包可以不同价，班级均价是加权值。
