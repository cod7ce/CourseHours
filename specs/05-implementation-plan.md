# 05 · 实现计划

八个阶段，每个阶段结束都应该是可运行、可演示的。**不要并行开工，按顺序来** ——
后面每一层都依赖前面的账本语义正确。

---

## P0 骨架

- `electron-vite` 起项目，React + TS + 路由
- better-sqlite3 接上，`electron-rebuild` 跑通
- migration runner（读 `db/migrations/*.sql`，按文件名顺序执行，记录在 `_migrations` 表）
- 跑 `001_init.sql`（= 01 文档的全部 DDL）
- `setting` 表读写 + 默认值 seed
- 侧边栏 + 空白路由页，样式 token 建成 CSS 变量

**验收**：应用能启动，侧边栏 6 个入口能切换，数据库文件在 userData 下建出来，设置能存能读。

## P1 主数据

- student / klass / enrollment 的 CRUD 仓储
- 学生列表页、班级列表页、班级详情页（名册部分）
- 新建学生、新建班级、加入班级、移出班级

**验收**：能手工录入 5 个班 40 个学生，班级详情能看到名册。此时余额都是 0。

## P2 排课

- `core/scheduling.ts`：规则 → 日期展开（纯函数）
- 循环规则 CRUD
- 批量生成（幂等，R5）+ 预览干跑
- 课表周视图
- 单次取消、临时加课

**验收**：配好 5 条规则，点一次生成 2 周，课表上出现 18 节课；再点一次生成，不产生重复；取消一节，课表上变灰且不顺延。

## P3 点名与账本 ★ 核心

这是整个 MVP 的心脏，慢一点没关系，错了后面全错。

- `core/hours.ts` + `core/balance.ts` + `core/packages.ts`（纯函数，先写测试）
- **把 02 文档里所有「边界用例」表格逐行写成单测，先让测试全绿**
- `ledger_entry` 仓储（只有 insert，没有 update/delete）
- 点名事务（R1）
- 点名页 UI（照抄 `Roster.dc.html` 的交互逻辑）
- 撤销与调整（R4）

**验收**：
- 给一个学生手工插一条 recharge +24，点 3 次名后余额 = 21
- 余额 0 的学生点名后变 −1，流水里 `package_id IS NULL`
- 撤销后余额回到 −0，原行加删除线，多出一条 adjust 行
- `SUM(delta)` 与每行 `balance_after` 始终一致（写个断言脚本跑全表）

## P4 充值与抵扣

- `core/recharge.ts`（两种方式，R3）
- package 仓储 + 充值页 UI
- 课包预设从设置读
- 学生详情的课包卡片 + 流水里的抵扣说明

**验收**：余额 −2 的学生充 10 课次 ¥1,000，方式 A 后余额 = 8、`offset_sessions = 2`、实收 ¥1,000；方式 B 后余额 = 10、实收 ¥1,300、多一条 adjust +2。

## P5 学生视图与全局流水

- 学生列表的余额排序、筛选、应补缴金额
- 学生详情完整版（横幅、课包、流水分页）
- 全机构流水页 + 筛选 + 分页
- 今日页（依赖前面全部）

**验收**：今日页能正确显示今天 3 节课、待点名的预计扣课时、3 个预警学生。

## P6 报表

- `core/reports.ts`（R6 全部口径）
- 报表页：4 个 KPI、两组图、班级明细表
- CSV 导出

**验收**：手工核对一个月的课消课时 = 流水里 consume 的 delta 绝对值之和；未消耗和已欠两个数分开且都对。

## P7 设置全量 + 打磨

- 五个设置分区全部接上真实读写
- 提醒：每日推送、预警阈值、排课提醒
- 备份：`VACUUM INTO` + 定时 + 保留份数
- 导出全部数据、从备份恢复、清空数据
- 二次确认、toast、键盘快捷键
- electron-builder 打包出 dmg

**验收**：改扣课时规则后，新点的名按新规则扣，历史流水不变；备份文件能恢复成功。

---

## 建议的第一周

P0 + P1 + P2 的骨架大约是一周的量（全职）。
**但如果时间紧，优先级是 P0 → P3 → P4**，先把「点名扣课时 + 充值抵扣」这条主线跑通，
班级和排课可以先用直接写 SQL 的方式塞种子数据。因为这个系统的价值全在账本上，
排课界面再漂亮，账算错了就没用。

## 测试策略

- `core/` 纯函数：**必须有单测**，覆盖 02 文档全部边界用例
- 仓储层：用内存 SQLite（`new Database(':memory:')`）跑集成测试，重点测事务原子性
- UI：不做自动化测试，人工过一遍 12 屏
- **一个必须有的断言脚本**：全表扫描，校验每个学生的 `SUM(delta)` 与最后一条 `balance_after` 相等，以及 01 文档列的 9 条不变量。每次大改后跑一次。
